# 单应与 Warping（Homography & Warping）学习笔记

## 原理

**单应（Homography）**是一个 3×3 齐次变换矩阵，描述两个平面（或同一平面在不同相机位姿下的成像）
之间的投影关系：

```
[x']   [h11 h12 h13] [x]
[y'] = [h21 h22 h23] [y]
[w']   [h31 h32 h33] [1]
```

它有 8 个自由度（可归一化 h33=1）。当场景是平面、或相机绕光心旋转（无平移）时，两图间的关系
精确是单应。求解单应需至少 4 组点对应，常用 **DLT（直接线性变换）+ RANSAC** 鲁棒估计。

**Warping（图像变换）**是把图像映射到新坐标系。OpenCV 用 `warpPerspective` 做单应变换，内部是
**后向映射**（对输出每个像素，反查输入位置），避免前向映射产生空洞。

## 背景

单应是几何视觉的基石：图像拼接、配准、AR、平面测距都依赖它。它把「两图之间的像素对应」压缩成
一个 8 参数矩阵，是第 7 章「特征匹配 + RANSAC」的直接应用。

## 解决的问题

| 技术 | 解决的问题 |
|---|---|
| 单应估计 | 描述两平面图像的投影关系 |
| warpPerspective | 把图像变换到目标坐标系（拼接/配准的几何变换） |

## 效果

- 对平面场景或纯旋转，单应能精确对齐两图。
- warp 后可把多图拼到统一坐标系。

## 局限

- 单应只对**平面场景或纯旋转**精确；有视差的非平面场景会产生对齐误差（需更复杂的多平面/深度模型）。
- `findHomography` 返回的方向约定（src→dst）易混淆，warp 方向错误会导致结果反向。
- warp 需提前计算画布尺寸容纳变换后的图像，否则内容被裁剪。

## 后续改良

- **RANSAC 变体**（MSAC/LMEDS/PROSAC）提升外点抵抗与收敛速度。
- **多单应**（对非平面场景，分割成多个平面分别估 H）。
- **Bundle Adjustment**（BA）全局优化所有单应与点，用于大规模拼接/SfM。

## 实际工程使用情况

- **图像拼接/全景**：两两估 H → 累计到参考坐标系 → 融合。
- **多摄对齐**：不同摄像头的图经 H 对齐。
- **AR / 平面追踪**：跟踪平面并叠加虚拟内容。
- **文档扫描校正**：把拍摄的倾斜文档校正为正面。

## 对硬件的额外诉求

- 单应估计依赖特征匹配（第 7 章），算力主要在特征检测/匹配，warp 是逐像素映射，中等算力。
- 手机上拼接的 warp 可在 GPU 上高效完成（纹理映射）。
